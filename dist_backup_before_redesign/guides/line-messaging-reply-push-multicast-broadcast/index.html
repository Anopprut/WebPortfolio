Reply, Push, Multicast, Broadcast ของ LINE ต่างกันอย่างไร

คำตอบสั้น: ใช้ Reply เมื่อตอบสิ่งที่ผู้ใช้เพิ่งส่งมา, Push เมื่อต้องการส่งหาคนใดคนหนึ่งเอง, Multicast เมื่อส่งหาคนหลายคนที่ระบุชื่อไว้, Broadcast เมื่อส่งหาทุกคนที่เป็นเพื่อนกับบัญชี

ตรวจข้อมูลเมื่อ 2026-10-10 จาก ข้อกำหนด OpenAPI ทางการของ LINE ค่าโควตาและราคาข้อความเปลี่ยนตามแพ็กเกจ ให้ดูที่เอกสาร LINE ล่าสุด

วิธีปลายทาง (endpoint)ส่งหาใครขีดจำกัดตามเอกสาร
ReplyPOST /v2/bot/message/replyคนที่เพิ่งส่งเหตุการณ์มา ใช้ replyTokenข้อความไม่เกิน 5
PushPOST /v2/bot/message/pushuserId / groupId เดียวข้อความไม่เกิน 5
MulticastPOST /v2/bot/message/multicastuserId หลายคนผู้รับไม่เกิน 500, ข้อความไม่เกิน 5
BroadcastPOST /v2/bot/message/broadcastทุกคนที่เป็นเพื่อนข้อความไม่เกิน 5

วิธีเลือกใช้ในงานจริง

  • บอตตอบลูกค้า: ใช้ Reply เสมอ เพราะผูกกับบทสนทนาและไม่ต้องรู้ userId ล่วงหน้า
  • แจ้งเตือนออเดอร์/นัดหมาย: ใช้ Push (ต้องมี userId เก็บไว้ตอนลูกค้าเพิ่มเพื่อน)
  • ข่าวถึงกลุ่มที่เลือกไว้: ใช้ Multicast แล้วแบ่งรายชื่อเป็นชุดละ 500
  • ประกาศทั่วไป: Broadcast แต่ควรมีขั้นอนุมัติก่อนเสมอ เพราะส่งแล้วยกเลิกไม่ได้

ตัวอย่างใน n8n (HTTP Request)

POST https://api.line.me/v2/bot/message/broadcast
Authorization: Bearer {Channel access token}
Content-Type: application/json

{
  "messages": [ { "type": "text", "text": "โปรโมชันวันนี้" } ],
  "notificationDisabled": false
}

ถ้าคำขอ Broadcast อาจถูกลองซ้ำเมื่อเครือข่ายขัดข้อง ข้อกำหนดของ LINE มีส่วนหัว X-Line-Retry-Key สำหรับป้องกันการส่งซ้ำ ให้ตั้งค่าเป็น UUID เดิมเมื่อ retry (อ่านรายละเอียดที่เอกสาร LINE)

โหนดชุมชนใน n8n

โหนด n8n-nodes-line-messaging รองรับ Reply, Send (Push), Multicast ณ วันที่ตรวจ ยังไม่เห็น Broadcast ในรายการการทำงานของโหนดนี้ ถ้าต้องใช้ ให้ใช้ HTTP Request ตามตัวอย่างด้านบน

ผมไม่ได้ทดสอบกับ channel จริงในบทความนี้ ตัวอย่างทั้งหมดอ้างอิงข้อกำหนดทางการ

อยากให้ผมทำให้? รับทำระบบอัตโนมัติ n8n, LINE OA / Telegram Bot และงานเชื่อมระบบสำหรับร้านค้าและทีมเล็ก ดูบริการของผมบน Fastwork ส่งโจทย์มาให้ประเมินขอบเขตและราคาก่อนจ้างได้

คำถามที่พบบ่อย

Reply กับ Push ต่างกันอย่างไร?

Reply ตอบกลับเหตุการณ์ที่เพิ่งเกิดขึ้นโดยใช้ reply token ที่ได้จาก webhook ส่วน Push ส่งหาผู้ใช้เมื่อไรก็ได้ด้วย userId แต่ Push ใช้โควตาข้อความของบัญชี

Multicast ส่งได้กี่คน?

ตามข้อกำหนด OpenAPI ของ LINE ระบุผู้รับได้สูงสุด 500 userId ต่อคำขอ และแต่ละคำขอใส่ข้อความได้ไม่เกิน 5 ข้อความ

Broadcast ส่งหาใคร?

ส่งหาผู้ใช้ทั้งหมดที่เพิ่มบัญชีเป็นเพื่อน ใช้ระวังเพราะกระทบผู้ใช้ทุกคน และตรวจโควตาก่อน
